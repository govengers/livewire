# Generated clients

`generate.Write(registry, options)` writes the clients of a registry (D19, D61): the TypeScript client with its runtime and Vue composables, the OpenAPI 3.0.3 document, the Go client and the command-line client. Every file starts with `Code generated by livewire. DO NOT EDIT.`, is deterministic for one registry and options, and is committed; `generate.Render` renders the same files in memory, which `livewiretest.GeneratedIsCurrent` compares with the committed ones ([Testing](Testing.md#generatediscurrent)). The todo app keeps its options in one place, for its generator command and its test:

<!-- snippet: examples/todo/internal/generated/generated.go#options -->
```go
// Options are the generator's options with every path below root, the module's directory.
func Options(root string) *generate.Options {
    return &generate.Options{
        TypeScriptDirectory: filepath.Join(root, "web", "src", "api"),
        OpenAPIFile:         filepath.Join(root, "openapi.yaml"),
        OpenAPI: generate.OpenAPIOptions{
            Title:       "Todo",
            Version:     "1.0.0",
            Description: "The livewire example: todos of a workspace, live over a WebSocket.",
            SecuritySchemes: []generate.SecurityScheme{
                {Name: "session", Type: "apiKey", In: "cookie", ParameterName: "__Host-auth_session", Description: "The session cookie of a password login (auth_session over plain http in development)."},
                {Name: "apiKey", Type: "http", Scheme: "bearer", Description: "An API key from POST /api/v1/keys (D20)."},
            },
        },
        GoClient:    generate.GoClientOptions{Directory: filepath.Join(root, "client", "todoclient"), ImportPath: modulePath + "/client/todoclient"},
        CommandLine: generate.CommandLineOptions{Directory: filepath.Join(root, "client", "todocommand"), Name: "todo"},
        Enums:       []generate.Enum{generate.EnumOf(api.Priorities()...)},
        Presence:    true,
    }
}
```

- Every output is optional; `TypeScriptDirectory`, `OpenAPIFile`, `GoClient.Directory` or `CommandLine.Directory` turns one on.
- `Enums` lists the values of named string types (`generate.EnumOf(api.Priorities()...)`), which reflection cannot enumerate; an `enum:"a,b"` tag on a field wins.
- `Presence` says the engine has a `PresenceStore`; only then are the presence reads, routes and joins generated, as only then does the REST adapter mount them.
- The mapping of Go types is encoding/json's (D63): a pointer, a nil-able slice or map is `| null`, `omitempty` and `omitzero` make a field optional, `time.Time` and `uuid.UUID` are strings, a guarded field is optional. `Write` refuses what it cannot describe: a type encoding/json cannot marshal, identifiers that collide, a Go client type it cannot import.

## TypeScript

The directory gets `types.ts` (the DTOs and the library's wire types), `filters.ts` (a filter document type per resource), `api.ts` (one REST function per read, mutation, upload and export, and the descriptors `reads`, `live`, `calls`, `uploads`, `downloads`), and copies of `runtime.ts` and `vue.ts`. It type-checks under `strict`, `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess`. There is no global state: every function takes the `Client` or `LiveConnection` it runs on.

- `Client` is REST: `getTodos(client, { filter, sort, limit })`, `createTodo(client, body)`, `uploadAttachment(client, { id }, file)`, `downloadTodosExport(client, query)`. Every mutation gets an `Idempotency-Key` (a UUID v7) and a ClientID create an `id` when its body has none.
- `LiveConnection` is the socket: `connection.subscribe(live.todos, parameters, listener)`, `connection.query(...)`, `connection.call(calls.createTodo, parameters, body)`, `connection.batch(...)`, `connection.join(...)`. It reconnects with backoff and subscribes everything again, every subscription starting with a snapshot; every request settles within `requestTimeout` (30 s) or on its `AbortSignal`.
- A refusal is an `ApiError` (`status`, `code`, `fields`, `body`), a failure to reach the server a `NetworkError`, a request of an ended client or connection an `EndedError` whose `sent` says whether it went out.
- Both re-send an evicted unnamed filter inline once on a 404 (D54).

### One pair per identity

A `Client` and a `LiveConnection` serve the identity their `identity()` option answers when they are made, for their whole life (D66). Whatever detects another one ends them: `checkIdentity()` (which they run before requests, subscribes, connects and pings), a 4401 close, or the application's `end()`. Ending fails every queued and pending request with an `EndedError`, drops every subscription's data and, in a pair, ends the other half. Neither can see a session cookie, so the application ends the pair before the request that changes the session, and makes the next one afterwards. From [examples/todo/web/src/live.ts](../../examples/todo/web/src/live.ts):

<!-- snippet: examples/todo/web/src/live.ts#pair -->
```ts
/** The pair of one identity, "provider:subject" as the server's session answers it, "" for nobody. */
const pairOf = (identity: string): LivePair => createLivePair({
  identity: () => identity,
  client: { baseURL: '/api/v1' },
  connection: { url: () => `${location.protocol === 'https:' ? 'wss' : 'ws'}://${location.host}/api/v1/socket` },
})

/** The pair every composable follows: app.use(plugin), then await resume(); a login or logout replaces it. */
export const pair = shallowRef(pairOf(''))
export const plugin = livePlugin(pair)
```

<!-- snippet: examples/todo/web/src/live.ts#change-session -->
```ts
async function changeSessionNow(change: () => Promise<Response>): Promise<void> {
  pair.value.end()
  let failure: unknown
  try {
    const response = await change()
    if (!response.ok) failure = new Error(`the session change answered ${response.status}`)
  } catch (error) {
    failure = error
  }
  await resume()
  if (failure !== undefined) throw failure
}
```

The status of a connection is `idle`, `connecting`, `open`, `reconnecting` or `ended`. A retried mutation keeps its body's id and its key: `prepareCall` fills both once, and a `NetworkError` that is not an `EndedError` may be retried with them:

<!-- snippet: examples/todo/web/src/live.ts#optimistic-create -->
```ts
/**
 * Creates a todo on the socket with an optimistic effect (D36): the list shows it at once,
 * pending, under the id the client chose (D18), and the same id and Idempotency-Key go out on a
 * retry, so a retried create runs once (D16). Only a lost answer is retried: a refusal (an
 * ApiError, `conflict` when the id exists) answers the same again, and an ended pair serves no
 * one any more.
 */
export async function createTodo(title: string): Promise<TodoItem> {
  const connection = pair.value.connection
  const prepared = prepareCall(calls.createTodo, { title, priority: 'high' })
  try {
    return await connection.call(calls.createTodo, {}, prepared.body, { idempotencyKey: prepared.idempotencyKey })
  } catch (error) {
    if (error instanceof NetworkError && !(error instanceof EndedError)) {
      return connection.call(calls.createTodo, {}, prepared.body, { idempotencyKey: prepared.idempotencyKey })
    }
    throw error
  }
}
```

### Vue

`app.use(livePlugin(pair))` provides the pair's reference; every composable follows it, dropping the old pair's data and subscribing on the new. `useLive(target, parameters)` is one live read (`data`, `error`, `stale`, `loading`, `pending`, `retry()`); `useLiveList` keeps filter, sort and page state (`items`, `total`, `filter`, `sort`, `limit`, `page`, `pages`; in cursor mode `loadMore()` and `hasMore`); `useLiveStatus` is the connection's status; `useLivePresence` joins a record with a state and lists who else is there:

<!-- snippet: examples/todo/web/src/live.ts#views -->
```ts
/** The todo list view: the filterable, paged live list with the summary and the activity. */
export function useTodoList() {
  const todos = useLiveList(live.todos, { sort: ['-createdAt'], limit: 25 })
  todos.filter.value = { where: { field: 'done', op: 'eq', value: false }, search: 'milk' }
  const summary = useLive(live.summary, {})
  const activity = useLive(live.activity, {})
  const status = useLiveStatus()
  const first: TodoItem | undefined = todos.items.value[0]
  const open: number | undefined = (summary.data.value as SummaryItem | undefined)?.open
  const latest: ActivityItem | undefined = activity.data.value?.items[0]
  return { todos, summary, activity, status, first, open, latest }
}
```

`useLive(target, parameters, { cache: true })` keeps the last data in `localStorage` and shows it, stale, before the socket answers (D21). A snapshot belongs to the identity that received it: none is kept without an identity, the plugin removes an identity's snapshots when its pair ends, and another identity clears them all.

## OpenAPI

The document covers every route: the reads with their reserved parameters, a filter schema per resource, `ListResponse` schemas, mutations, uploads (raw and multipart), the export (`text/csv`), batch and the stored filters, and the error responses with the closed code set. Nullable fields are `nullable: true` (3.0.3, D26). Extensions: `x-websocket: {target, ops}` on every operation the socket serves too, `x-livewire-guarded` on guarded fields, `x-livewire-effect` on mutations with an effect. The file is JSON under the generated header, which YAML reads, so its name must not end in `.json`; the application serves it if it wants to. `just openapi-breaking` compares the example's document with a previous tag's ([Testing](Testing.md#breaking-changes-of-the-api)).

## Go client

`GoClient{Directory, ImportPath, Package}` writes a package `<app>client` on the runtime `livewire/client` (D67). It imports the application's DTO packages and authenticates with an API key (D20), sent as `Authorization: Bearer`:

<!-- snippet: examples/todo/cmd/todo/main_test.go#go-client-new -->
```go
todos, err := todoclient.New(&client.Options{BaseURL: a.baseURL(), APIKey: a.apiKey(t, username)})
```

- One method per read (`GetTodos`, `GetTodosItem`, ...), live read (`SubscribeTodos`, ...), mutation (`CreateTodo`), upload and export (into an `io.Writer`, failing on a cut export). Parameters are the client's own structs (`TodosListQuery`, `UpdateTodoParameters`).
- Mutations and uploads go over REST. `*client.CallOptions{IdempotencyKey}` sets the key, a fresh UUID v7 without one; `PrepareCreateTodo(body)` fills a ClientID create's id and a key to send on every retry; `BatchCreateTodo(body)` builds one call of `Batch`.
- Filters are typed per resource, as in TypeScript ([Stored filters](Reads-and-Filters.md#stored-filters)). A refusal is a `*client.Error{Status, Code, Message, Fields}`.
- `Subscribe...` delivers `client.Push[Data]{Kind, Data, Change, Err}` on a channel that closes when ctx ends or after an error push; `Data` is the state after the push. One socket per client carries every subscription and reconnects with backoff; a consumer far behind gets the current state instead of every step. A 4401 or a 401 at the handshake ends the live side for good with `*client.EndedError`; REST goes on.

<!-- snippet: examples/todo/cmd/todo/client_test.go#go-client-subscribe -->
```go
pushes, err := alice.SubscribeTodos(ctx, todoclient.TodosListQuery{})
require.NoError(t, err)
snapshot := nextPush(t, pushes)
require.Equal(t, livewire.PushSnapshot, snapshot.Kind)
require.Empty(t, snapshot.Data.Items)

created, err := carol.CreateTodo(t.Context(), api.CreateTodoRequest{Title: "from carol"}, nil)
require.NoError(t, err)
change := nextPush(t, pushes)
require.Equal(t, livewire.PushListChange, change.Kind)
require.Len(t, change.Data.Items, 1)
require.Equal(t, created.ID, change.Data.Items[0].ID, "the same workspace, another user, over the change feed")
```

## Command-line client

`CommandLine{Directory, Package, Name, EnvironmentPrefix}` writes a package with `Command()` on urfave/cli/v3 and `Run`, the whole of a binary's main (D68):

<!-- snippet: examples/todo/cmd/todo-cli/main.go#cli-main -->
```go
func main() {
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
    code := todocommand.Run(ctx, os.Args, os.Stdin, os.Stdout, os.Stderr)
    stop()
    os.Exit(code)
}
```

- The tree: `<declaration> list|get|item|distinct|history|presence|export` per read, one command per mutation and upload, `batch`, `filters save|list|delete`, and `subscribe <declaration> <kind>`, which writes one NDJSON line `{kind, data}` per push until interrupted. Names are kebab-case: `todo create-todo --body '{"title":"milk"}'`, `todo todos list --sort -createdAt`.
- Parameters are typed flags; the reserved ones are `--filter`, `--filter-id`, `--sort`, `--limit`, `--offset`, `--after`, `--field`. A body is `--body` or stdin; `--idempotency-key` repeats a call safely; an upload sends `--file` with `--content-type`; an export goes to stdout or `--output`.
- `--base-url`, `--api-key` and `--socket-url` fall back to `TODO_BASE_URL`, `TODO_API_KEY` and `TODO_SOCKET_URL` (the prefix is the name upper-cased).
- The server's JSON goes to stdout as it is, diagnostics to stderr. Exit codes: 0 success, 1 failure (5xx, the network, a cut export), 2 usage, 3 refusal (4xx, an ended live side).
